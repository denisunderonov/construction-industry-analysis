# Construction Industry Analysis

Небольшой pet-проект по исследованию строительного рынка России на данных ФНС.

В проекте я собрал реестр компаний с ОКВЭД 41.20 — «Строительство жилых и нежилых зданий», очистил и подготовил данные, дополнил их финансовыми показателями и географией, а затем провёл исследовательский анализ.

Цель проекта — не просто построить несколько графиков, а попробовать пройти полный путь аналитика: от сырых данных и их подготовки до визуализации и выводов.

## Что я исследовал

- какие компании входят в выбранную выборку;
- как строительные компании распределены по регионам;
- где сосредоточено больше всего компаний;
- какие компании заметно выделяются по финансовым показателям;
- как отличаются показатели компаний между собой;
- есть ли заметные связи между выручкой, прибылью и другими финансовыми показателями.

## Данные

Основой проекта стал реестр субъектов малого и среднего предпринимательства ФНС.

Из исходного набора я отобрал:

- юридические лица;
- субъекты малого и среднего предпринимательства;
- основной ОКВЭД 41.20 — строительство жилых и нежилых зданий.

Для финансового анализа данные по компаниям дополнительно собирались из бухгалтерской отчётности через `bo.nalog.ru`.

Для пространственного анализа адреса компаний были геокодированы и использованы вместе с геоданными.

## Стек

`Python` · `Pandas` · `NumPy` · `Matplotlib` · `GeoPandas` · `Requests` · `Geopy`

## Что сделал

### 1. Подготовил данные

Провёл фильтрацию исходного реестра, очистил данные и оставил только компании, которые соответствуют условиям исследования.

### 2. Собрал финансовые показатели

Для компаний получил данные из бухгалтерской отчётности и объединил их с основным реестром.

В анализе использовал, в частности:

- выручку;
- прибыль до налогообложения;
- чистую прибыль;
- процентные расходы;
- EBIT как доступный показатель операционной прибыли.

EBITDA в проекте не рассчитывалась, поскольку в доступной структуре данных не было достаточно информации для корректного восстановления амортизации.

### 3. Провёл географический анализ

Адреса компаний были преобразованы в координаты. Это позволило посмотреть на распределение строительных компаний не только в виде таблиц, но и на карте.

### 4. Построил визуализации

В ноутбуке представлены графики и карта, которые помогают увидеть структуру выборки, региональное распределение и различия между компаниями по финансовым показателям.

Основные визуализации:

- распределение компаний по регионам;
- сравнение финансовых показателей;
- анализ наиболее заметных компаний;
- географическая карта компаний.

## Основные наблюдения

По результатам анализа видно, что строительный рынок в выбранной выборке распределён по России неравномерно: количество компаний заметно отличается от региона к региону. Наибольшая концентрация наблюдается в крупных экономических центрах, что соответствует высокой деловой активности и объёму строительства в этих территориях.

Финансовые показатели компаний также сильно различаются. В выборке есть большое количество относительно небольших организаций и отдельные компании с существенно более высокими значениями выручки и прибыли. Поэтому средние значения без дополнительного контекста могут искажать представление о типичной компании.

При сравнении финансовых показателей становится заметна разница между масштабом бизнеса и его прибыльностью: высокая выручка сама по себе не означает пропорционально высокую чистую прибыль. Для оценки компании поэтому полезно смотреть сразу на несколько показателей, а не только на оборот.

Географическая визуализация дополнительно показывает, что компании формируют заметные локальные концентрации. Карта хорошо дополняет обычную группировку по регионам, поскольку позволяет увидеть пространственную структуру данных.

## Что получилось в итоге

Этот проект стал для меня практикой полного аналитического цикла:

`данные → очистка → сбор дополнительных данных → объединение → исследовательский анализ → визуализация → выводы`

При этом я отдельно столкнулся с реальными проблемами, которые обычно не видны в учебных датасетах: неполными данными, разными форматами полей, ограничениями внешних источников и необходимостью обрабатывать ошибки при сборе информации.
